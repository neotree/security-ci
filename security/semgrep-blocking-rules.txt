# Semgrep rules that BLOCK the build even though their severity is WARNING.
#
# The Semgrep job blocks on ERROR. Most community rules ship as WARNING, which left SQL
# injection, hardcoded JWT/session secrets, XXE, SSRF and TLS bypass as advisory-only
# annotations nobody is obliged to read. These are the high-confidence ones: each names a
# concrete vulnerability class rather than a hygiene or configuration preference.
#
# Deliberately NOT here (they stay advisory): cookie/header/CORS configuration audits,
# React/DOM HTML sinks (sanitised usage is common and legitimate), directory listing,
# sendFile, JWT revocation, cloud-infrastructure and Angular audit rules.
#
# Every id must exist in semgrep-rules.yml or semgrep/ - a test enforces it, so a typo
# cannot silently match nothing. Matching is by dotted suffix, because Semgrep prefixes
# each id with the path of the config file it was loaded from.
